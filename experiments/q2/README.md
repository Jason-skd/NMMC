# 题 2 实验与逻辑链条（接手指南）

本目录是题 2 **诊断 → 修正 → 复核**这条链上的可复现脚本，以及**还没跑完**的实验队列。
交付代码在 `src/nmmc/`，本目录不参与交付，只保证"别人能按同一条思路继续往下跑"。

运行前提：`.venv` 已就绪（`uv sync`）。一律用 `.venv/bin/python`，**不要用 `uv run`**——
本机 sandbox 下 uv 会因 `bin/prob1` 权限报错。

---

## 0. 三十秒版本

题 2 的病不在执行层，在 **$u$ 的可行域**：v5 把紧急购电写成"无上界、按 $\kappa p_t$ 计费"，
于是它多了一重题面没给的身份——日内采购通道。平价段 5 倍价买入折损后 4.44 元/kWh，
比晚峰 5 倍价 6.98 元便宜，所以逾四成紧急电量是**囤货**不是断供。
v6 加了一条零参数线性上界 $u_t\le(n_t-g_t)^+$，全年费用 +0.17%（23,338 元），
换来 $u\wedge c=0$、光伏盈余时段买入 0、峰段占比从 27% 升到 52%。

一句话判据：**改动如果只让指标好看、总费用却上升，那不是改进，是以钱买心安。**
这是本链条唯一的验收标准，扫任何参数都先看总费用。

## 1. 逻辑链条（每一环都有对应脚本 / 产物）

| 环 | 问题 | 做法 | 产物 / 结论 |
|---|---|---|---|
| ① 现象 | v5 的 C14 归因健康度不过，紧急购电 2174 时段 | 读全年摘要 | `results/q2_v6/L1-P1-R2-smpc-nocap/q2_summary.md`（= v5 口径） |
| ② 排除"次数失控" | 4.52% 是不是太高？ | 与报童临界频率比 | $1-\alpha^\star=(\kappa-1)/(\kappa-\theta)$ 在 $\theta=\eta^2$ 下 = 4.5%，**逐位吻合，次数是设计值** |
| ③ 逐时段重放 | 紧急购电发生在什么水位、当步在充还是在放 | `diag_slots.py` | 近半电量发生在 SOC>8000；放电顶功率上限只占 0.3%；71% 的时段放电为 0 |
| ④ 机制分类 | "有电不放"里哪些是病 | `diag_mechanism.py` | 拆成**囤电型**（当步 SOC 上升 ⟺ $c>0$）与**真缺口**；囤电型 100% 满足 $p_t/\max p_{\text{剩余}}<\eta^2$ |
| ⑤ 排除"裕度不足" | 是不是日前买少了？ | `plan_sensitivity.py --bump 50` | 加厚裕度费用 **+4.79%**、弃电 +65%——中午容量与充电功率双紧，存不下 |
| ⑥ 反事实 | 加上界会怎样 | `legacy_counterfactual_ucap.py`（已被 src 实现取代） | 69 天 +0.68%（**外推不准，全年实测只有 +0.17%**） |
| ⑦ 落地 | 进模型 | `src/nmmc/model/q2.py` + `run/q2.py` | 四条臂同口径；`--no-emerg-cap` 精确复现 v5（逐日 $\Delta Z<5\times10^{-7}$ 元） |
| ⑧ 判据修正 | 为什么 C14 永远过不了 | `src/nmmc/report/q2.py` | 旧 ③ 把**配给型**（最优）与**囤电型**（缺陷）焊成一类；拆开后 C14a–d 全过 |
| ⑨ 复核 | 上界改变了 §11.4 的前提吗 | `plan_sensitivity.py` | 裕度那点已复核（结论不变）；**$\nu^{\mathrm{end}}$ 三点还没跑 → 见 §3** |

详细论证：`docs/题2-SOC与紧急购电诊断.md`（病因证据链）、`docs/题2-v6修正报告.md`（修正与全年数字）、
`docs/题2变量定义.md` §5.1 / §6.1 / §7.6 / 性质 8′ / C14 / C16（模型条款）。

### P0｜$\nu^{\mathrm{end}}$ 在新口径下重扫（**已完成**）

产物 `results/gap-checks/nu_*.csv`。窗口 day 100–119 相对交付 615,622 元：

单调变差，锚点仍最优。变量档 §11.4 可按新口径引用。

### P1｜执行层情景日内更新

现在剩余时域仍用 0:00 的残差贴加，日内不更新（读法 C 其实允许更新）。这解决的是**真缺口那一侧**
（约四成紧急电量），与本轮的口径问题正交。落点：`src/nmmc/run/q2.py` 的 `run_smpc_day`，
每 6 或 12 个时段用当日已实现残差重建情景集。验收看 $Z^{\mathrm{online}}$ 与"实时信息损失"
（$Z^{\mathrm{online}}-Z^{\mathrm{ex\text{-}post}}$，现在 283,773 元）同时下降。

### P2｜$3\times3\times2$ 预报网格重跑

v5 起结论作废、接口未变。18 组 × 30 分钟 ≈ 9 机时，必须按组合并行分片（组合之间独立）：

```bash
.venv/bin/python -m nmmc.cli.prob2 --load L2 --pv P3 --resid R1 --output-dir results/q2_grid
```

⚠️ 网格只用来选预报候选，**不要**顺手拿它当"调参"——选出的组合必须在变量档 §3 有机制解释。

### P3｜题 3 / 题 4 的口径对齐

题 3 的上界应写成相对**最终购电量**的缺口 $u_t\le(n_t-a_t)^+$。题 3 交付臂实测 $u\wedge c=0$、
紧急占比 1.23%，囤电动机已被性质 10 的门槛 $\beta^+\eta^2=1.215<3.7576$ 自然掐断，**故不必改**；
但题 4 换成波动价 $p^{(j)}_t$ 后门槛要逐时段重判，那时必须回到这条上界。

## 4. 明确不要做（都已被证否，别再走一遍）

1. **把 $g$ 整体上抬"修故事"**——§11.4（v5 口径）与本目录 `plan_sensitivity.py --bump 50`
   （v6 口径）两次证否：紧急指标变好、总费用上升。
2. **把 $\alpha^{\mathrm{rt}}$ 请回交付臂**——随机 MPC 已把这个人工调参维度消掉，它只作为 $Z^{\mathrm{CE}}$ 消融对照存在。
3. **扫 $\nu^{\mathrm{end}}$ 去"抬高 SOC 均值"**——SOC 均值不是判据（题 1 的水位在费用上退化，扫描带宽 0.24%），
   而且会涨钱。要比水位就比**隔夜**水位（C5 已改口径）。
4. **在中间迭代里挑 $\tilde Z$ 最好的那一轮**（§6.1）——不同轮次可行域不同，$\tilde Z$ 跨轮不可比，
   只有不动点自洽。
5. **用固定轮数代替不动点判据**——曾用 `passes=2`，全年 16 天残差 $>10^{-3}$，最差日当天费用虚高 2.9%。
