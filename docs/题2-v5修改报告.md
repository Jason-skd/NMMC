# 题 2 v5 修改报告（执行层：确定性等价 MPC → 在线随机 MPC）

日期：2026-09-12。口径：组合 **L1-P1-R2**，334 个交付日（2.1–12.31；1 月暖机不计费用）。原始求解摘要见 `results/q2_v5/q2_summary.md`。

本轮**没有**单独的变更说明；建模意图写在 `docs/题2变量定义.md` 修订记录与 §7，全年数字在 `results/q2_v5/`。这份报告把「改了什么、数字变成什么样、故事圆没圆」收成一页。

---

## 1. 为什么改

v4 交付的执行层是**确定性等价 MPC**：剩余时域压成一条 $\alpha^{\mathrm{rt}}=0.65$ 分位参考路径。全年回测故事讲不通——不是求解器坏了，是把「未来可能缺口」当成「一定发生」，储能影子价格被钉在 $\kappa p^{\mathrm{p}}\eta$，谷时宁可以 5 倍价囤电也不放电。

v4（同一组合、同一规划层 $g$，`results/q2/L1-P1-R2`）三条硬伤：

| 现象 | v4 数字 | 为何不合格 |
|---|---:|---|
| 紧急购电同时充电 | 1676 时段（3.5%） | 性质 8：最优 $g$ 本可用 1 倍价提前储备 |
| 紧急购电的电价分布 | 谷 51% / 峰 8% | 真缺口应出现在峰时 |
| 缺口时段频率 | 11.2% | 性质 5 预言应显著低于 $1-\alpha^\star\approx 4.5\%$ |
| 归因 ③有电不放（SOC>3000） | **86.5%** | 电池有电仍付 5 倍价 = 执行层指纹 |

规划层不是病因：day 100–119 上抬 $\nu^{\mathrm{end}}$ 或给情景加 50/100 kWh 裕度，紧急指标变好看，总费用一律变差（变量档 §11.4）。本轮规划层、预报层接口都不动，$3\times3\times2$ 消融不重跑。

## 2. 改了什么

**唯一结构变化在执行层。** 每个时段 $t$ 解一个两阶段 LP：当步 $(c,d,u,w)$ 与 $S_{t+1}$ 在情景间共享（用**真值** $n_t$、真实 SOC），剩余时域按 0:00 情景集分支。只执行当步。影子价格按缺口**发生概率** $q$ 折算，不再令 $q\equiv 1$。

副产物：交付策略不再有人工分位 $\alpha^{\mathrm{rt}}$。$\nu^{\mathrm{end}}=0.472$ 仍是全模型唯一外生参数。v4 的确定性等价 MPC 留作对照 $Z^{\mathrm{CE}}$。

| 层 | 本轮 |
|---|---|
| 预报 | 不动。默认仍 L1-P1-R2（近 4 个同星期几 × 近 7 日光伏 × 近 12 条残差） |
| 规划 | 不动。日前 SAA + $\nu^{\mathrm{end}}=0.472$ |
| 执行 | **交付改为** `policy=smpc`（`simulate_stochastic`）；原 `mpc` 降为对照 |
| 结算 | 不动。现金 $Z=\sum p g+\kappa\sum p u$ |
| 诊断 | 新增紧急购电三分类 + 谷/峰/盈余占比；摘要输出 EVPI 二分解与执行层消融 |

代码与测试：

| 文件 | 变更 |
|---|---|
| `src/nmmc/q2.py` | `solve_stochastic_step` / `simulate_stochastic`；`attribute_emergency`；默认 `policy="smpc"` |
| `src/nmmc/cli/prob2.py` | 默认交付 smpc；全年对照加跑 CE / 事后 / PI |
| `src/nmmc/q2_report.py` | 摘要增加归因、电价分段、执行层消融表 |
| `tests/test_q2.py` | 情景退化为真值复现事后最优；C9 序关系；末时段不白弃电（C15）；smpc 紧急量低于 CE |
| `docs/题2变量定义.md` | v5 修订记录、§7 重写、C14/C15、§11.4 |

跑法：`uv run prob2 --combo L1-P1-R2 --output-dir results/q2_v5 --write-details`（本机约 14 分钟，含三条对照）。

未改：预报候选实现、阶段 1 LP、物理可行域、result2 填表规则。v4 的 18 组消融排序在新执行层下作废，本轮不引用、不重跑。

## 4. 自检（对照变量档 C9 / C14 / C15）

| 项 | 判定 | 说明 |
|---|---|---|
| C9 序关系 | 过 | 12.25M ≤ 13.39M ≤ 13.72M |
| C15 末时段估值 | 过 | 测试锁定 $w_{144}\approx 0$；日末 SOC 7806 kWh，与 v4 同量级 |
| C14 ③有电不放为少数 | **不过** | 62% 仍是第一大类 |
| C14 峰价占比 > 谷价占比 | 过 | 27.5% > 15.6% |
| C14 盈余时段近零 | **不过** | 9.5% |
| 紧急同时充电 | 未清零 | 598 时段 |

变量档 C14 写的是判定性条款：「三条任一违反，不得交付」。按字面 **v5 仍不能当终稿交付**。费用和缺口率已经像样，故事只圆了一半：谷时 5 倍囤电的极端形态被打破了，但「电池有电还付 5 倍价」没有从主因变成残差。

文档修订记录里「三条硬伤同时收敛」是按 20 日预实验写的，**全年数字不支持把这句话写进论文**。应以本报告 §3 表为准。

## 5. 还没圆的部分、下一步不该做什么

剩余 62% 的 ③ 不是「规划裕度不够」。§11.4 已经试过加厚 $g$：紧急变少、总账变差。再扫 $\nu^{\mathrm{end}}$、再跑 18 组预报网格，解决不了「实时子问题仍把未来缺口估偏」。更可能的方向：

1. **执行层情景未日内更新。** 当前 smpc 的未来分支仍是 0:00 残差贴加，上午已经看见的阴晴/负载水平没有灌回剩余时域。读法 C 允许用「今日已实现」去校正未来情景，这不是偷看。
2. **0:00 情景集对尾部缺口有偏。** 变量档 §7.6 已写：③ 仍高就回查残差贴加。这是预报/情景的问题，不是再加一层人工 $\alpha$。
3. **598 个 $u>0$ 且 $c>0$ 的时段**仍是性质 8 的红灯，应在明细里按电价段拆开，确认是不是末段估值或功率上限的数值残差。

明确不做：重跑 $3\times3\times2$；把规划层 $g$ 整体上抬当「修故事」；把 $\alpha^{\mathrm{rt}}$ 请回交付策略。
